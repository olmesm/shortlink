REST API

Authentication

Every /rest/v1 endpoint requires an API key, sent as X-Api-Key: <key> (or Authorization: Bearer <key>). Keys are created in the dashboard or via the API and shown exactly once. Roles:

RoleScope
adminfull access
authorsees and manages only short URLs created with that key
domainrestricted to one domain

Errors are RFC 7807 application/problem+json. List endpoints accept page and itemsPerPage and return a pagination envelope. Mutating calls are rate limited per client IP. GET /rest/health needs no auth.

Quick example

> curl -H "X-Api-Key: $KEY" -H "Content-Type: application/json" \
    -d '{"longUrl":"https://example.com/landing","customSlug":"promo","tags":["marketing"]}' \
    https://sho.rt/rest/v1/short-urls

Short URLs

EndpointNotes
GET /rest/v1/short-urls searchTerm, tags, tagsMode=any|all, startDate, endDate, domain, orderBy=dateCreated|shortCode|longUrl|title|visits with -ASC/-DESC, excludeMaxVisitsReached, excludePastValidUntil
POST /rest/v1/short-urls longUrl (required), customSlug, shortCodeLength, domain, title, tags, maxVisits, validSince, validUntil, forwardQuery, crawlable, redirectStatus, findIfExists
GET /rest/v1/short-urls/{code} optional ?domain= on all {code} routes
PATCH /rest/v1/short-urls/{code} partial update; send null to clear title, maxVisits, validSince, validUntil
DELETE /rest/v1/short-urls/{code}
GET / POST /rest/v1/short-urls/{code}/redirect-rules POST replaces all rules; condition types: device, language, query-param, ip-address
GET /rest/v1/short-urls/{code}/visits startDate, endDate, excludeBots
DELETE /rest/v1/short-urls/{code}/visits
